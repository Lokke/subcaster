# SubCaster Docker Configuration

This directory is mounted into the Docker container at `/app/docker-data` to persist configuration.

## 🚀 Quick Start (Automatic)

The easiest way to start SubCaster with Docker is using the startup script:

```bash
# Linux/Mac
bash docker-start.sh

# Windows
docker-start.bat
```

These scripts automatically:
- Create the `docker-data` directory with correct permissions
- Generate a `.env` template if missing
- Build and start the Docker container
- Handle permission issues automatically

## 📋 Manual Setup

If you prefer manual setup or encounter permission issues:

### 1. Create Directory and Set Permissions

```bash
# Linux/Mac
mkdir -p docker-data
chmod 777 docker-data

# Create .env file
touch docker-data/.env
chmod 666 docker-data/.env

# Windows (Run as Administrator)
mkdir docker-data
icacls docker-data /grant Everyone:(OI)(CI)F
```

### 2. Configure via Setup Wizard

1. Start the container: `docker-compose up -d`
2. Open http://localhost:3002
3. Complete the Setup Wizard
4. Configuration will be saved to `docker-data/.env`

### 3. Or Copy Existing Config

```bash
# Copy your existing .env
cp .env docker-data/.env

# Ensure correct permissions
chmod 666 docker-data/.env
```

## 🔒 Security Notes

- This directory is in `.gitignore` and will NOT be committed
- Never commit `.env` files to version control
- The `.env` file contains secrets (tokens, passwords)
- Secrets are only accessible server-side (not in browser)

## 🐛 Troubleshooting

### Permission Denied Error

If you see "EACCES: permission denied" when saving configuration:

```bash
# Fix: Make directory writable by container
chmod 777 docker-data
chmod 666 docker-data/.env

# Or use the startup script:
bash docker-start.sh
```

### Container Can't Write Files

The container runs as user `nodejs` (UID 1001) for security. The mounted volume must be writable:

```bash
# Check current permissions
ls -la docker-data

# Fix permissions
sudo chown -R 1001:1001 docker-data
# OR make world-writable:
chmod 777 docker-data
```

### Startup Script Fails

If `docker-start.sh` fails:

1. Ensure Docker is running: `docker ps`
2. Check script permissions: `chmod +x docker-start.sh`
3. Run with sudo if needed: `sudo bash docker-start.sh`

## 🔄 Updates

When updating SubCaster:

```bash
cd /var/subcaster/subcaster
git pull
bash docker-start.sh  # Rebuilds with --no-cache
```

The `docker-start.sh` script handles everything automatically.
